# Reproducing analyses and figures

This guide describes the order of operations for reproducing the analyses in this repository. Figure 1 is a task-design illustration and has no analysis script. Figures 2-8 and S1-S5 have scripts; several EEG figures depend on intermediate files generated by earlier steps.

The code repository does not contain the study data. Obtain the de-identified data from the associated UQ data repository and configure local paths as described below. Do not add raw data, derivatives, caches, or generated figures to the code repository.

## 1. Environment and project setup

The analyses were run with Python 3.12.7 and MNE 1.8.0 in the established MNE environment. [`environment.yml`](../environment.yml) records the direct analysis dependencies and their known-working versions. It is a portable Conda environment specification rather than a platform-specific lock file. `mne-faster` is installed through pip; it is needed for EEG preprocessing. Parquet read/write support is provided by `pyarrow`.

The examples in this guide use Bash and POSIX-style paths. From a terminal, set the project folder, create and activate the Conda environment, then run analysis modules from the project root:

```bash
project="$HOME/path/to/TG-MotEst-02-reproducible-pipeline"
cd "$project"

source "$(conda info --base)/etc/profile.d/conda.sh"
conda env create -f environment.yml
conda activate motest-analysis

python --version
python -c 'import mne; print("MNE", mne.__version__)'
```

On HPC systems, load or initialize Conda using the instructions for that system before activating the environment. If the environment is already installed, skip `conda env create`.

## 2. Configure data and output locations

For the directory layout `TG-MotEst-02/rawdata` and `TG-MotEst-02/derivatives`, configure the paths below, replacing the example parent directory with the actual data location:

```bash
data_root="/path/to/TG-MotEst-02"
export MOTEST_EXP1_RAWDATA="$data_root/rawdata"
export MOTEST_EXP2_RAWDATA="$data_root/rawdata"
export MOTEST_DERIVATIVES="$data_root/derivatives"

export MOTEST_CACHE_DIR="$project/outputs/cache"
export MOTEST_FIGURE_DIR="$project/figures/generated"
```

The current tested setup uses the same raw-data root for both experiments. If the behavioural data are separated, set each raw-data variable to its experiment-specific root. Behavioural scripts look for participant folders under these paths and tab-delimited files in each participant's `beh` folder.

`MOTEST_DERIVATIVES` must point to a directory containing participant folders such as `sub-001`. EEG analysis scripts read their per-participant `eeg` and `eeg/FE` subfolders. Caches and figures go to the configured locations; defaults are `outputs/cache` and `figures/generated`.

“Full-window” refers to decoder products spanning `-0.95..2 s`; “cropped” refers to the `-0.25..2 s` portion used by group summaries and models. Prediction epochs and metrics are distinct files: the metrics conversion step consumes the prediction epochs and writes participant-level metric parquets. S1 requires cropped main-decoder products; S2/S3 require full-window within-prior metrics that are cropped when aggregated; S4 requires full-window within-prior prediction epochs and metrics that are cropped when summarized; and S5 requires full-window products from **both** decoder modes using the alternate S5 baseline. Do not substitute the standard-baseline derivatives for S5 inputs.

### Batch/HPC use

The processing command operates on one participant per invocation. Forward encoding, metric conversion, and temporal generalisation default to processing all participant folders; `--subject sub-001` limits each command to one participant. This lets you arrange one invocation per batch job using your site's scheduler and resource policy, without requiring a particular HPC system or prescribing how jobs are parallelized.

Keep project code and the Conda environment available on compute nodes, and ensure each job receives the same `MOTEST_DERIVATIVES` configuration and can read the relevant participant inputs. After activating the environment and setting the data paths in your job, the commands for participant `sub-001` are:

```bash
subject="${MOTEST_EXP2_RAWDATA}/sub-001"
python -m analysis.eeg_processing.processEEG "$subject" "$MOTEST_DERIVATIVES"
python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis main --subject sub-001
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis main --subject sub-001
```

Temporal generalisation can also run once per participant as its own batch job:

```bash
python -m analysis.decoding.forward_encoding.FE_tempgen_localDev --subject sub-001
```

It writes matrices beneath that participant's `eeg/FE/train_sk2_unif/tempGenMats` directory. The figure-generation step aggregates participant matrices into `$MOTEST_CACHE_DIR/allTempGenMats.h5` (or `outputs/cache/allTempGenMats.h5` by default), so wait until all participant jobs have completed before running Figure 5 or Figure 8; do not launch figure aggregation concurrently with those jobs. If an aggregate already exists and a participant matrix is newer, the loader rebuilds the aggregate.

Use `--analysis within-prior` for the within-prior decoder and metrics. For S5, use `--baseline s5` for preprocessing, and add `--baseline s5 --time-window full` to the decoder and metric commands. Launching a decoder before that participant's clean epochs exist, or converting metrics before that participant's prediction epochs exist, will fail explicitly for a selected subject. Forward encoding and temporal generalisation use joblib with `n_jobs=-1`, so each process uses the CPUs visible to it. Ensure this matches the resources allocated to each job when choosing CPU, memory, wall-time, and concurrency settings for your cluster.

## 3. Optional EEG preprocessing

Skip this section if the derivatives already contain the clean epoch files required by the analyses.

The hosted raw-data repository provides the expected participant/session folder layout and BIDS-compatible EEG filenames under `rawdata/sub-.../eeg`, with matching behavioural TSV files under `rawdata/sub-.../beh`. No file-renaming step is required.

The preprocessing command processes one participant per invocation and writes that participant's derivatives under `$MOTEST_DERIVATIVES`:

```bash
subject="$MOTEST_EXP2_RAWDATA/sub-001"
python -m analysis.eeg_processing.processEEG "$subject" "$MOTEST_DERIVATIVES"
```

Repeat this command for each participant folder. The script reads BDF and behavioural files, performs filtering, epoching, and MNE-Faster/ICA cleaning, and can take substantial time. By default it uses the standard `-0.35..-0.25 s` baseline. Check that each participant has clean epoch files for both sessions before proceeding. CPP and the standard decoder expect names following this pattern:

```text
sub-001_ses-MAIN-01_task-TG-MotEst-2.0_t--0.95-2_bl--0.35--0.25-0.2-40bpf-clean_epo.fif.gz
sub-001_ses-MAIN-02_task-TG-MotEst-2.0_t--0.95-2_bl--0.35--0.25-0.2-40bpf-clean_epo.fif.gz
```

### Alternate baseline and full time window for Supplementary Figure S5

S5 requires separate clean epochs baseline-corrected to `-0.95..-0.85 s`. Generate them for each participant with `--baseline s5`:

```bash
python -m analysis.eeg_processing.processEEG "$subject" "$MOTEST_DERIVATIVES" --baseline s5
```

These are separately labelled and do not overwrite the standard-baseline epochs. To generate S5's full `-0.95..2 s` decoding predictions and metrics, use both `--baseline s5` and `--time-window full`. The commands below show all-participant invocations; add `--subject sub-001` to each forward-encoding or metric-conversion invocation to run one participant at a time:

```bash
python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis main --baseline s5 --time-window full
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis main --baseline s5 --time-window full

python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis within-prior --baseline s5 --time-window full
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis within-prior --baseline s5 --time-window full
```

This produces the four S5-required per-participant intermediates: main-decoder prediction epochs and metrics, plus within-prior prediction epochs and metrics. Every file is labelled `t--0.95-2_bl--0.95--0.85-0.2-40bpf-clean` and is stored in its decoder directory under `eeg/FE/` (metrics are in `decoding_metrics/`). Generate all four products for every participant before running S5. Use these products only for S5; standard analyses continue to use the default baseline and cropped prediction window.

## 4. Behavioural figures (Figures 2 and 3)

These analyses are independent of EEG preprocessing and decoding. With both raw-data paths configured, run:

```bash
python -m analysis.behaviour.behavioural_figs
```

The script filters aborted and very fast trials, calculates behavioural accuracy and bias, fits the figure-level mixed models, and saves `E1_bhv_results.svg` and `E2_bhv_results.svg` under `$MOTEST_FIGURE_DIR`.

## 5. CPP analysis and Figure 4

This requires clean EEG epochs for both sessions for every participant. It uses EEG channels CP1, CPz, CP2, Cz, and Pz and the behavioural trial metadata attached to the epochs.

First create the time-resolved CPP model fit:

```bash
python -m analysis.statistics.CPP
```

This aggregates the CPP data, fits timepoint-wise mixed models, and saves `cpp_model_fit.pkl` and an intermediate parquet file under `$MOTEST_CACHE_DIR`. Then generate Figure 4:

```bash
python -m analysis.erp.generate_fig04
```

Figure 4 independently prepares or loads its plotting-data cache from the configured derivatives, reads `cpp_model_fit.pkl`, and saves `fig04.svg` under `$MOTEST_FIGURE_DIR`. Run the model step before the figure step. The behavioural figures and CPP analysis/Figure 4 have been successfully run with the current data.

## 6. Main EEG decoding and dependent figures

These steps are compute- and memory-intensive. They are listed for completeness and are not required for the behavioural or CPP checks above.

### 6.1 Main forward-encoding predictions and metrics

Run the main decoder across participants, then convert its prediction epochs into per-trial decoding metrics:

```bash
python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis main
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis main
```

Predictions and metrics are written below each participant's `eeg/FE/train_sk2_unif` directory. The main model-fitting scripts and figures read metrics from this directory.

### Figure 5

Figure 5 uses main decoding metrics, sensor-regression results, and temporal-generalisation matrices. After the main predictions and metrics above, run:

```bash
python -m analysis.decoding.MixedLM_sensors
# Run once per participant, e.g. via separate scheduler jobs:
python -m analysis.decoding.forward_encoding.FE_tempgen_localDev --subject sub-001
# Wait until all subject jobs have completed before making figures.
python -m analysis.decoding.generate_fig05
```

The sensor-regression step writes `sensor_reg_stats_all.pkl` to the cache. The temporal-generalisation step writes subject-level matrices under `train_sk2_unif/tempGenMats`; the group HDF5 aggregate is stored at `$MOTEST_CACHE_DIR/allTempGenMats.h5` (or `outputs/cache/allTempGenMats.h5` by default). Sensor regression and temporal generalisation can take substantial time and use parallel workers.

The main decoder loads the latest clean `-0.95..2 s` epochs and crops its predictions to `-0.25..2 s`. Figure 5 uses these cropped prediction metrics, while its sensor topomaps load and crop the full clean epochs. Current labels end in `bpf-clean`; the extra legacy suffix is no longer used.

### Figures 6 and 7

After the main decoding metrics exist, fit each model and run its figure:

```bash
# Figure 6 accuracy model and figure
python -m analysis.statistics.MixedLM_FE --dv accuracy
python -m analysis.decoding.generate_fig06

# Figure 7 bias model and figure
python -m analysis.statistics.MixedLM_FE --dv bias
python -m analysis.decoding.generate_fig07
```

The fits save `fe_acc_model_fit.pkl` and `original_bias_model_fit.pkl` under `$MOTEST_CACHE_DIR`. The figures are `fig06.svg` and `fig07.svg`.

### Figure 8

Figure 8 uses temporal-generalisation matrices. Generate them with `FE_tempgen_localDev` for each participant as in the Figure 5 sequence. Wait until all subject jobs have completed, then run:

```bash
python -m analysis.decoding.generate_fig08
```

It aggregates the subject-level matrices if the cache does not already contain the group HDF5 file and saves `fig08.svg`.

## 7. Within-prior decoding and supplementary figures

Within-prior products are kept separate from the main decoder. Per-participant files go under `eeg/FE/train_within_prior_resamp_binned`; group caches and model fits go under `$MOTEST_CACHE_DIR/within_prior`.

### 7.1 Within-prior predictions and metrics

Within-prior participant metrics are generated over the full `-0.95..2 s` window. The standard group summaries, linear models, and plots then crop those metrics to `-0.25..2 s`, matching the main analyses. Run both stages with `--time-window full`:

```bash
python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis within-prior --time-window full
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis within-prior --time-window full
```

These steps are computationally intensive. Use the same `--analysis` selection for both commands.

### Supplementary Figures S2 and S3

Fit each within-prior model, then generate the corresponding figure:

```bash
# S2 accuracy
python -m analysis.statistics.MixedLM_FE_within_prior --dv accuracy
python -m analysis.supplementary.generate_figS2

# S3 bias
python -m analysis.statistics.MixedLM_FE_within_prior --dv bias
python -m analysis.supplementary.generate_figS3
```

Model files and aggregated caches are under `$MOTEST_CACHE_DIR/within_prior`. Figures are saved as `figS2.svg` and `figS3.svg`.

### Supplementary Figures S1 and S4

The shared `plot_tuning_functions.py` script accepts an analysis mode:

After preparing the prediction and metric data, select the matching mode:

```bash
# S1: original/main decoder
python -m analysis.supplementary.plot_tuning_functions --analysis main

# S4: within-prior decoder
python -m analysis.supplementary.plot_tuning_functions --analysis within-prior
```

It saves `figS1.svg` or `figS4.svg` according to the selected mode. The default is `--analysis within-prior`. S4 uses the within-prior cache and prediction directory.

S1 uses the same cropped main-decoder predictions and metrics as the main decoding analyses. Generate them with:

```bash
python -m analysis.decoding.forward_encoding.FE_full_pipeline --analysis main
python -m analysis.decoding.forward_encoding.FE_chans2metrics --analysis main
```

Figure 5 and S1 use cropped `t--0.25-2...bpf-clean` main-decoder products. S2/S3/S4 load full-window `t--0.95-2...bpf-clean` within-prior products and crop them to `-0.25..2 s` in group summaries, models, and plots. S5 is the separate full-window, alternate-baseline exception described below. Current labels use `bpf-clean` without the obsolete extra suffix.

### Supplementary Figure S5

S5 requires **both decoder analyses**, each using full-window (`-0.95..2 s`) predictions generated from the alternate-baseline (`-0.95..-0.85 s`) clean epochs. For every participant, the following four files must exist:

- Main decoder: `eeg/FE/train_sk2_unif/sub-*_task-TG-MotEst-2.0_t--0.95-2_bl--0.95--0.85-0.2-40bpf-clean_FE-pred-epochs.fif.gz` and the matching `decoding_metrics/*_FE-metrics-long.parquet`.
- Within-prior decoder: `eeg/FE/train_within_prior_resamp_binned/sub-*_task-TG-MotEst-2.0_t--0.95-2_bl--0.95--0.85-0.2-40bpf-clean_FE-pred-epochs.fif.gz` and the matching `decoding_metrics/*_FE-metrics-long.parquet`.

Generate the alternate-baseline clean epochs and both pairs of decoder files using the commands in Section 3. Generating only the main decoder products or only the within-prior products is not sufficient.

Run:

```bash
python -m analysis.supplementary.generate_figS5
```

The script aggregates those participant-level metrics into the main cache and `$MOTEST_CACHE_DIR/within_prior`, applies its time alignment, and saves `figS5.svg`. Do not reuse cropped-window or standard-baseline outputs.
